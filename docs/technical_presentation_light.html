Data Grounding

Structured APIs before LLM reasoning

Why: LLMs hallucinate drug data. Structured APIs don't.

ClinicalTrials.gov API

  • Trial status, phase, conditions, endpoints
  • Grounds the research planner — prevents TA misclassification
  • Example: "SYH2082" → conditions: "Overweight or Obesity" → cardio_metabolic
  • Without it: Haiku guessed "NSCLC / oncology" for a GLP-1 drug

PubMed E-utilities API

  • Full abstracts with efficacy/safety data
  • Fallback for preclinical — when no trials exist, MOA papers ground the planner
  • 8 articles for BNT327, 0 for TERN-701 (early-stage, expected)

OpenFDA API

  • Orphan drug, fast track, breakthrough designations
  • Ground truth — merged into de-risking signals even if LLM missed them
  • Deterministic: either you have the designation or you don't

Tavily Web Search

  • Conference posters (ASH, ASCO, ESMO), analyst coverage, deal news
  • Fills gaps not in structured databases
  • Used by science agent (1 search), market agent (3), synthesizer (4)
  • Non-deterministic — results vary across runs

Valuation

Three scenarios × two views

Every number shown as both risk-adjusted (with PTRS) and if-succeed (assumes approval)

A. Standalone NPV

Asset's own patient population

if_success = peak_standalone
× rev_mult × npv_discount

risk_adj = above × PTRS

B. Platform / Displacement

+ SOC capture if best/better-in-class

if_success = peak_displacement
× rev_mult × npv_discount
+ optionality premium

risk_adj = above × PTRS

C. Strategic Deal Price

What the winning bidder actually pays

deal_mult = base(phase)
+ urgency + bidding
+ differentiation

if_success = peak_disp × deal_mult

PTRS (Probability of Technical & Regulatory Success) is computed in Python, not by the LLM. Base rate from phase × TA lookup table, adjusted by up to 9 de-risking signals (orphan, breakthrough, patients dosed, etc). Capped per phase.

Deal Economics

Dual mode: M&A vs. Licensing

Always compute both — buyer compares before choosing structure

M&A / Acquisition

  • Buyer acquires entire company/asset
  • Upfront ≈ total (buyer takes all risk)
  • Territory: always worldwide
  • Royalties: none (owns 100%)
  • Milestones: small CVR/earnout only
TERN-701: predicted $5.2B upfront
Actual Merck deal: $5.7B

Licensing / Partnership

  • Buyer licenses specific program(s)
  • Upfront = 25-50% of total (risk shared)
  • Territory: worldwide / ex-US / ex-China
  • Royalties: 15-30% of net sales (NPV)
  • Milestones: regulatory + commercial stack
BNT327: predicted $3.8B up / $12.7B total
Actual BMS deal: $3.5B up / $11.1B total

Frontend toggle lets users switch between modes instantly — same underlying valuation, different deal economics layer.

Converting to MCP would enable reuse across clients (Claude Desktop, other agents) and LLM-driven tool selection.

Science MCP Server

Internal data sources exposed as MCP tools for the science agent:

  • Internal clinical database — proprietary trial results, IND filings, CMC data not on ClinicalTrials.gov
  • KOL / medical affairs notes — advisory board insights, conference debriefs, competitive intelligence
  • Preclinical data warehouse — in vivo/in vitro results, PK/PD models, toxicology for early-stage assets
  • Patent / IP database — freedom-to-operate analysis, patent cliff dates, exclusivity periods

Commercial MCP Server

Internal data sources for the market agent + synthesizer:

  • EvaluatePharma / GlobalData — consensus analyst peak sales forecasts (replaces Tavily for market sizing, eliminates variance)
  • Internal deal database — proprietary deal terms, board decks, IC memos from past transactions
  • Pricing & market access models — internal revenue forecasts, payer landscape, reimbursement data
  • CRM / pipeline tracker — which assets BD team is already tracking, meeting notes, term sheets in progress

Why MCP? Model Context Protocol standardizes tool interfaces — same tools work with Claude Desktop, Claude Code, Slack bots, or any MCP-compatible client. Build once, use everywhere across the organization.

Considerations

Open questions and tradeoffs

Data & Accuracy

  • Peak sales variance — largest source of output instability. Consensus forecasts or internal models would make this deterministic
  • Multi-asset platform deals — system evaluates single assets; cannot bundle 8 programs like AZ/CSPC $18.5B deal
  • Territory-specific modeling — licensing territory (ex-US, ex-China) defaults to worldwide; needs UI selector and market fraction data
  • Paywalled literature — science agent cannot access NEJM/Lancet full text; institutional access would improve evidence quality

Infrastructure

  • Latency — ~30-60s per analysis (sequential pipeline, 4 LLM calls + 13 API calls). Caching and parallel searches could reduce this
  • Cost — ~$0.15-0.30 per analysis (Sonnet ×3 + Haiku ×1 + Tavily ×8). Internal data would reduce Tavily dependency
  • Caching — no result caching today; same asset queried twice runs full pipeline both times

Model & Reliability

  • LLM non-determinism — temperature 0.2 means ~10-20% variance in outputs. Lower temperature = more consistent but less nuanced
  • JSON parse failures — no retry logic; single malformed LLM response produces fallback/empty data
  • Deal multiple self-capping — model sometimes computes a high multiple then self-caps to a lower value (conservative bias)
  • Hallucinated metrics — LLM may fabricate efficacy numbers if Tavily/PubMed return sparse data

Enterprise Readiness

  • Authentication — no user auth; single-tenant only
  • Audit trail — no persistent logging of analyses or assumptions
  • Data governance — internal data via MCP needs access controls and compliance review
  • Model evaluation — need systematic benchmarking against historical deals (beyond 4 test assets)
